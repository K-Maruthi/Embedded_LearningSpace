1. PROJECT SNAPSHOT
--------------------------------------------------------------------------------
Name        : Embedded Learning Space (com.embeddedc.learning.space)
Version     : 1.0.0
Purpose     : Desktop wrap of a browser-local, single-page Embedded C learning
              roadmap — from bit-level C fundamentals through Cortex-M
              compilation, linking, startup and system-level failure analysis.
Shell       : Tauri 2 (Rust), window 1440x920 (min 1050x700), NSIS + MSI bundles,
              WebView2 downloadBootstrapper install mode.
Frontend    : One standalone HTML file (src/index.html, ~765 KB) produced by a
              concatenation build from roadmap-source/ fragments. Zero runtime
              dependencies: no CDN, no backend, no framework. Vanilla ES5-style
              JS in IIFEs, custom SVG force-graph, own tiny markdown renderer.
Data model  : 7 stages / 163 topics / 8 lenses / 10 memory-map regions,
              25 interview questions (4 tracks x 2 levels x 4 formats),
              10 fault-triage scenarios, 5 failure-pattern clusters,
              7 compiler diffs, 109 canonical topic-metadata entries.
Persistence : localStorage only, namespaced ecroadmap.* (done, notes, marks,
              theme, interview answers, fault state). Versioned JSON
              export/import for full-state backup.
Build chain : roadmap-source/build.sh -> embedded-c-roadmap.html -> copied to
              src/index.html (verified byte-identical at time of this report)
              -> packaged by Tauri via frontendDist "../src".
Commands    : npm install | npm run dev (tauri dev) | npm run build (tauri build)
              Artifacts land in src-tauri/target/release/bundle/.

3. CURRENT PROJECT HEALTH
--------------------------------------------------------------------------------
Strengths
  - Zero-dependency, fully offline, single-file app; reproducible build.
  - Canonical topic registry + startup validation prevents content drift.
  - Strong pedagogy: lens model, note-gated mastery, causal-order exercises,
    teach-back drills, self-graded rubrics.
  - src/index.html confirmed in sync with the last standalone build.

Weaknesses / risks
  W1  (CLOSED) roadmap-source -> src/index.html sync is automated by
      `npm run build:roadmap` (validate + concat + copy in one command).
  W2  No automated tests beyond id/reference validation. Lab models (section
      placement, bit ops, struct layout, edge builder) are regression-prone.
      (Partially improved: Rust pipeline/toolchain now has 8 unit tests +
      an --ignored live-toolchain integration test, all passing.)
  W3  CSP is null in tauri.conf.json; the app renders stored user markdown.
      Escaping is done manually (esc/md) — one gap becomes an XSS surface.
      (Risk slightly raised by bench mode: user C code round-trips through the
      DOM — all rendered via esc()/hl(), kept monospace-only, no markdown.)
  W4  localStorage in WebView2 can be wiped by browser/OS cleanup; backups are
      opt-in and easy to forget. No automatic timestamped backup.
  W5  Export uses DOM anchor download rather than a native save dialog.
  W6  Monolithic ~800 KB generated HTML, ~2,700-line app file, ES5 idiom;
      hard to review, no module boundaries, no linting setup.
  W7  Content depth is uneven: 163 roadmap topics vs 10 fault scenarios,
      25 interview questions, 7 diffs — practice loops run dry quickly.
  W8  No app version/changelog surface in UI; package.json, Cargo.toml and
      tauri.conf.json each carry "1.0.0" manually (three sources of truth).
  W9  Mobile (Tauri 2 supports iOS/Android) and multi-language not addressed.
