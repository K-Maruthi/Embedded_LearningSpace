        Peripheral Playground

        Ten stages from “what is a register” to interrupts that preempt each other

        Work the stages in order — each one gives you only the registers it teaches, and ends in a goal the model grades against the live machine. Most goals read register state; the last one also grades behaviour over time, because a handler that fires once and stops still leaves every register looking correct. Behind every bit you flip there is hardware you can watch: the pin’s MOSFET cell, the counter’s waveform with a draggable ARR line, a swim-lane timeline of who owns the CPU, and a behaviour tape of what the CPU actually did. Or jump to stage 10, the full playground with fixed, correct preset programs. Nothing here is guesswork: the model is small and honest about the simplifications it makes.

        Protocol Lab

        How bits actually travel a wire

        Registers decide a voltage; protocols are what a second device infers from that voltage over time. The module is grouped the way the hardware is: Basics (line physics, and the seven questions every serial protocol answers), then UART, I²C (including how a slave can stall the clock), SPI and CAN — each a set of graded stages on the same logic-analyser instrument. Everything is a live model, exactly like the Peripherals tab: watch the signal, read the code it equals, break it on purpose.

        Memory-map lab

        Type a declaration and drop it in. This is a simplified teaching model, not a real compiler — it applies storage duration, const-ness and initialisation rules to show where the object lives. Declarations without auto/register are treated as file-scope; explicit automatic objects such as auto int x = 0; are shown in the runtime stack.

          .textcode size unknown

          Flash: 0 B RAM: 0 B

          Function definitions land in .text; this model doesn't estimate code size. The stack is runtime RAM, not an ELF section: automatic objects occupy stack-frame space only while their block is active. The lab's RAM total includes the explicitly modelled stack bytes.
