### Compilation Path: the Teaching / Lab bench decision (2026-09-30)

The question was whether Lab bench needs its own preprocess / compile / assemble views
beside the editors. **Decision: no — one stage rail, two bodies.** The bench already reuses
the eight stage tabs, and stages 2–7 in bench mode render observations parsed from *your*
build plus your real artifacts; a parallel bench-only pipeline would duplicate the rail and
split one build across two UIs. What the bench did need was legibility, so:

- **Two reports.** `clab.report` is the fixed example; `clab.benchReport` is your build.
  `clabReport()` is the single place that picks one, so a bench build can no longer leak into
  the teaching stages (it used to: the teaching panel showed your custom artifacts).
- **Provenance everywhere.** Every artifact and facts panel now names its source — *your bench
  sources* vs *the fixed example* — and the bench warns until you have actually built.
- **The rail shows where a build stopped.** Per-stage ✓/✕ marks come from the report the mode
  is showing, and a failed bench build lands on the first failing stage, the way a compiler
  takes you to the first error.
- **A *Lab bench* badge** marks the stage head while the editors are in charge.

[specs/lab_compile.spec.js](specs/lab_compile.spec.js) (44 checks) pins the report split,
the provenance language, the output parsers, failure landing and the stage-id agreement
across the rail, `CLAB_TITLES`, `COMPILE_DATA` and `pipeline.rs`. Four negative controls were
run on patched copies (selection, provenance, failure-landing order, parser) and each failed
the spec. The spec earned its keep immediately: it found a UI pluralisation bug — "2 #define
**directories**" for "directives" — now `problems.md` P11.

Live check (preview, `__TAURI__` stubbed with a scripted failed build): rail marks read
`source:ok preprocess:ok compile:bad`, the head carried the *Lab bench* badge, the facts
header switched from "from the fixed example" to "from your bench build", the live note read
"gcc -S produced this assembly · failed · your bench sources", Build landed on **compile**, and
Teaching restored "the fixed example".

### Protocol pass (2026-09-30): CAN, clock stretching, and the spec that found two bugs

**Request:** *"update the protocols with animations and visuals and new protocols"*.

**Delivered** — [24_lab_protocols.js](roadmap-source/24_lab_protocols.js) went from 9 stages / 4
families to **12 / 5**, each new stage animated on the existing ticker and scrubbable:

- **CAN · Dominant wins** (11) — CANH/CANL wiring card with the 120 Ω terminators, a hand-drivable
  wired-AND, then two nodes transmitting in lockstep: a per-bit LA with the divergence bit marked
  and a bit-by-bit *intent* table (A wants / B wants / bus reads). The winner is always the
  numerically smaller ID, because 0 is dominant — the goal verifies that, not just "a loser".
- **CAN · The frame** (12) — one 11-bit data frame built field by field with a real **CRC-15**
  (poly 0x4599) over SOF..DATA, drawn as a new **field-band** trace (one labelled band per
  field, bit grid underneath — 63–66 bits is unreadable as one box each), plus a **bit-stuffing**
  strip that highlights every inserted bit and prints the longest original run, and an **ACK slot**
  that goes recessive when the receiver is switched off. Goal: force stuffing (ID 0x000) and get
  an ACK.
- **I²C · Clock stretching** (10) — 0–6 held clocks after the slave's ACK, drawn as flat SCL-low
  slots, with a table proving the master's bit counter does **not** advance while the line is held.
- **Around it:** a CAN column in the stage-7 map (10 rows × 4 protocols), goal 7 spanning all four
  families, a `can` state group and `i2c.stretch` (filled field by field on load, so no schema
  bump), and `prLoad()`'s stage clamp changed from `1..9` to `!prStageById(n)` so adding a stage
  can no longer send a returning learner to stage 1.

**The new spec found two shipped bugs, and one of its own.**
[specs/protocol_stages.spec.js](specs/protocol_stages.spec.js) (143 checks) renders *every* stage
headlessly — `prBody()` is a pure function of the model — and on its first run it failed three

(**P14**); and one new CAN caption referenced an undefined `bits`, which would have left the

Also fixed while driving the preview: the scrubber's **"back to live"** control could never
appear (the bar is rendered once, before any scrub exists) — `problems.md` **P13**.

**Negative controls run for the new guards:** bus becomes OR (3), stuffing disabled (2), wrong
CRC on the wire (1), stretch holds SCL high (1), IDs sent LSB-first (3), address helper reverted
(3), data helper reverted (2), stretch builder loses its payload (4), a stage render throws (1),

**Live checks in the preview** (built HTML, real localStorage): the CAN family tab appears;

### Register-semantics pass (2026-09-30): a truthful register bank

**Request:** the peripherals gap analysis — *"write in docs and build it"*. The gap analysis
itself is catalogued in [features.md](features.md) under *Peripherals depth*; three of its
findings were defects, filed as [problems.md](problems.md) **P15–P17** and fixed in
[23_lab_periph.js](roadmap-source/23_lab_periph.js) (recorded as **I13** in
[improvements.md](improvements.md)):

- **P15** — `ISER0` toggled like plain RW: clicking a set bit cleared the line in the model
  with a whole-register write full of 0s, while the emitted C already said ICER. Now: ISER
  is write-1-to-set (0s ignored, masked to the two modelled lines, log note for the rest),
  ICER is write-1-to-clear and write-only (reads 0, dark card next to ISER0), and a clear
  click routes through ICER with the explanation in the log.
- **P16** — `PUPDR` existed in the model and prose but in no UI, so the floating-pad lesson
  could not be performed. Now a card (stages 3/4 + playground); clicks cycle a pin's whole
  2-bit field (never the reserved `11`), emit the two RMW statements, and are dropped when
  GPIOA is unclocked; the stage-3 pin cell follows pulls live.
- **P17** — `BSRR` taught stage 8's atomic lesson in prose but was absent from the bank
  (now a write-only card, reads 0, halves emitting `GPIO_BSRR_BS/BR<n>`); `CCR` was a
  floating slider admitting "visual duty only" (now a real timer row the slider writes,
  with the prose naming the genuinely-missing compare *output channel*); and unwired bits
  claimed "reserved in this model" (now "not wired in this model", striped, distinct from
  read-only).

**The spec** — [specs/periph_regs.spec.js](specs/periph_regs.spec.js), **99 checks** — drives
the model slice in a `vm` (set/clear through both NVIC registers, BSRR halves into ODR, the
pull cycle, CCR width, the emitted C), then renders all ten stages headlessly with the
no-`undefined` guard, checks reachability (PUPDR in 3/4, BSRR beside the race rig, both
NVIC rows in 6, the full bank in the playground), and calls every goal on a fresh lab. Its
first run caught a shipped hole of the P14 class: the stage-3 pin-cell SVG printed a bare
`undefined` inside `<g id="pf-pin5-pad">`. **Ten negative controls run on a patched copy**
(plain ISER assignment restored 8, ICER no-op 4, BSRR halves swapped 4, pull cycle reaching
11 2, BS macro on a reset 1, "reserved" title back 2, pin-cell `undefined` back 1, CCR row
dropped 1, resolver unshared 1, in-place ISER clear 1).

**Live checks in the preview** (built HTML, real localStorage): the lab boots to 10 stage
buttons and no leaks; a PUPDR click with GPIOA unclocked is dropped and logged, then cycles
0x000 → 0x800 (PA5 pull-DOWN) with the pin cell reading "pulled low — reads 0" and the
*Your code* panel showing both RMW lines; BSRR writes read `0x20 → 0x0` in ODR with the
emitted `GPIOA->BSRR = GPIO_BSRR_BS5;` / `…BR5;` lines; and the headline fix — clicking the
**set** ISER0 bit 28 flipped `0x10000000 → 0x00000000` **through ICER**, with the log note
explaining why ISER could not clear it in place.

### Linker-reader pass (2026-09-30): teaching what a `.s` actually is

**Request:** *"9. Reading a `.s`"* — the linker lab showed `startup.s` but never taught reading
it.

**Delivered** — [22_lab_linker.js](roadmap-source/22_lab_linker.js) gained a **ninth stage**,
*Reading a `.s`: what is actually an instruction*:

- **A histogram computed from the file, not typed in.** `asmClassify()` buckets `startup.s`'s
  58 lines into instruction / directive / label / comment / blank and the stage leads with
  "19 of 58 lines are instructions" — the vector table's `.word` directives counted as
  directives, because they emit bytes but are not code.
- **Anatomy.** Four real lines of the same file are taken apart field by field (label · mnemonic
  · operands · the encoded form), each decode read out of `STARTUP_S_LINES` at render time so the
  quoted text cannot drift.
- **Thumb-2** — the part line 6's `.thumb` had asserted since the first commit: why 16-bit Thumb
  had to drop instructions, what Thumb-2 adds back, and what that costs a reader (line 29 is four
  bytes, line 28 is two).

**The shipped bug it fixed.** The reset-walk pseudocode ended `bl SystemInit` then `bl main`,
while `startup.s` contained only `bl main` and `SystemInit` is defined **nowhere** in the project
— so a learner who typed the app's own lesson into the bench editor got `undefined reference to
SystemInit` (`problems.md` **P18**). The pseudocode now matches the file.

**The guards** — [specs/read_asm.spec.js](specs/read_asm.spec.js) (**144 checks**) re-derives
the classification independently and checks every decode and Thumb-2 pointer against the lines
they name; [specs/startup_pseudocode.spec.js](specs/startup_pseudocode.spec.js) (**70 checks**)
keeps the pseudocode and `startup.s` describing the same program. Both fail if the file is edited
underneath the prose, a decode's line number moves, or a symbol the lesson names is not in the
file.

### Peripherals time-base pass (2026-10-01): grade the deadline

**Request:** make the peripheral lab's time base, handler cost and deadline honest.

Three separate lies shared one cause (`problems.md` **P19–P22**), fixed in
[23_lab_periph.js](roadmap-source/23_lab_periph.js) and recorded as **I15**:

- **P19 · the time base.** `pfAdvanceTimer` stepped the counter by a clamped whole count
  (`Math.max(1, Math.round(100 / (PSC + 1)))`), so any divisor over 100 ran at 1/250th of the
  rate the card printed. The remainder now rides in `T.acc`, so `pfUpdateRateHz()` is exact at
  every PSC/ARR; `PF_MAX_ROLLS` bounds one tick's rollovers and `T.merged` counts the surplus
  past UIF's one bit.
- **P20 · the handler cost.** `PF_ISR_MS = 400` was quoted as a hardware fact. It is now
  labelled a model device everywhere — a real ISR is microseconds; 400 ms is four sim frames,
  chosen so preemption is visible at the 10 Hz tick — and every card that quotes it says "in
  this model".
- **P21 · the gate.** The tape graded cadence and freshness but not punctuality, so a saturated
  ISR — evenly spaced at the *cost*, not the requested rate — passed. `pfIsrDeadline(T)` returns
  `{periodMs, costMs, load, met}`; `pfTapeOnPeriod()` checks the measured cadence against the
  requested rate; and `pfTapeStillRunning()` now requires steady **and** fresh **and** on-period
  **and** deadline met. The timer row shows the deadline live (`.dl-ok` / `.dl-bad`), and the
  stage-9 band narrowed from 1.5–2.6 Hz to **1.5–2.4 Hz** (2.6 Hz is 385 ms, shorter than the
  handler).
- **P22 · stage 7's demo.** The nesting demo armed TIM3 at 5 Hz (200 ms) over the 400 ms handler,
  starving TIM2, so the stage's own `nestCount >= 1` goal was unreachable from its own button.
  TIM3 is now PSC 9 / ARR 79 (1.25 Hz, 800 ms); TIM2 stays 2 Hz. The 5 Hz case remains in the
  card as the counter-example.

**The guard** — [specs/periph_deadline.spec.js](specs/periph_deadline.spec.js), **129 checks**:
the time base, the deadline maths, the four-claim gate over scripted tapes, the nesting demo's
servable periods, the narrowed band, and drift guards so the prose, the card and the checklist
cannot be edited back into a different story than the grader. **37 negative controls** were run
against a scratch copy of the source (pointed at with the `PERIPH_SRC` env var) and all 37 were
caught — the harness copies rather than editing learner-facing source in place, after an early
in-place run left a mutation sitting in a comment.

Notes for whoever picks this up:

  cache-busting `?cb=` query.

- The negative-control habit is worth keeping: prove each new guard fails on a patched copy
  *before* trusting it. Recipe: copy the spec and the fragment into a scratch directory with
  the patched source and run the spec against it. (Use a scratch dir inside the repo — `/tmp`
  paths resolve awkwardly on this Windows setup.)

  that pattern rather than adding a test framework.
- `code_search`/ripgrep was unavailable in this environment; `grep`/`sed` via the terminal work
  fine.
